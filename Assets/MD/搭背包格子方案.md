# 搭背包格子方案（代码布局 + 对象池）

## 为什么不用 GridLayoutGroup？

GridLayoutGroup 会为每个物品创建一个 GameObject，500 个物品 = 500 个格子，Canvas 重建开销巨大。

代码布局 + 对象池只需要生成可见区域的格子（约 15~20 个），上下滑动时复用，性能稳定。

这是简历项目的技术亮点：**虚拟滚动 + 对象池回收**。

---

## 架构总览

```
SampleScene
└── Canvas
    └── BagPanel (Prefab)
        └── svBag (ScrollRect, 已配置)
            └── Viewport
                └── Content (只挂 RectTransform + BagGridLayout.cs)
                    ├── BagItemCell (对象池复用)
                    ├── BagItemCell (对象池复用)
                    └── ... (约 15~20 个，动态生成/回收)

C# 层（性能关键路径）:
  BagGridLayout.cs  — 挂在 Content 上，监听 ScrollRect，计算可见格子、驱动池
  BagItemPool.cs    — 对象池，预实例化/回收/清理

Lua 层（业务逻辑）:
  BagPanelCtrl.lua  — Tab 切换、数据加载、选中管理、调用 C# 刷新
  BagItemCell.lua   — 单个格子的点击/选中/长按/拖拽
```

## 第一步：BagItemCell 预制体结构

```
BagItemCell (根节点)
├── RectTransform
├── Image          — 格子底板/边框图（普通状态）
├── Button         — Transition = None，点击热区覆盖整格
├──2 imgIcon (Image)     — 物品图标，居中，约 100×100
├── txtCount (Text/TMP) — 数量文字，右下角
└── imgSelect (Image)   — 选中高亮框，默认不显示
```

**关键设置：**
- 根节点 SizeDelta = (160, 160)（格子大小）
- Button Transition = None（选中逻辑自己控）
- imgSelect 初始 SetActive(false)
- 所有子节点锚点正确设置（imgIcon 居中拉伸，txtCount 右下角）

## 第二步：C# 脚本

### BagGridLayout.cs（挂在 Content 上）

```
职责：
  1. 持有 ScrollRect 引用
  2. 配置参数：格子大小(cellSize)、列数(colCount)、间距(spacing)、内边距(padding)
  3. 根据 itemCount 动态设置 Content.sizeDelta 总高度
  4. 监听 ScrollRect.onValueChanged，计算当前可见行范围
  5. 驱动 BagItemPool：取出行内格子 → 设置位置 → 回收行外格子
  6. 提供 Refresh(itemCount) 公共方法供 Lua 调用
```

核心计算：

```
总行数 = ceil(itemCount / colCount)
Content.height = 总行数 × (cellSize.y + spacing.y) + padding.top + padding.bottom

格子(i) 的位置：
  col = i % colCount
  row = i / colCount
  x = padding.left + col × (cellSize.x + spacing.x) + cellSize.x / 2
  y = -(padding.top + row × (cellSize.y + spacing.y) + cellSize.y / 2)  // 从上往下

可见行范围：
  firstVisibleRow = floor(scrollRect.normalizedPosition.y 对应的 content 偏移 / (cellSize.y + spacing.y))
  lastVisibleRow = ceil((viewport.height + cellSize.y) / (cellSize.y + spacing.y)) + firstVisibleRow
  // 上下各多缓冲 1 行，避免滑动时出现空白
```

### BagItemPool.cs

```
职责：
  1. 持有 BagItemCell 预制体引用
  2. 预实例化 N 个格子（colCount × (visibleRows + 2)）
  3. Get(index) — 从池取一个格子，绑定到指定 index
  4. RecycleAll() — 全部回收
  5. 提供 OnCellBind 回调给 Lua 层刷新 UI
```

对象池容量：`列数 × (可见行数 + 2 行缓冲)` = 3 × (5 + 2) = **约 21 个格子**

### 为什么不用 Lua 做滚动计算？

ScrollRect.onValueChanged 每帧触发，Lua 与 C# 的跨语言调用在高频场景下有 GC 压力。滚动计算全部留在 C#，Lua 只负责数据绑定和 UI 刷新（低频：切换 Tab、绑定格子数据时）。

## 第三步：Lua 业务层

### BagPanelCtrl.lua

```
职责：
  1. 获取 C# 组件引用（ScrollRect、BagGridLayout、BagItemPool）
  2. 监听 Tab Toggle 切换，切换物品数据源
  3. OnTabChanged(tabType) → 加载对应物品列表 → 调用 bagGridLayout:Refresh(itemCount)
  4. OnCellBind(index, cellGo) 回调 → 从物品数据取数据 → 刷新 imgIcon/txtCount
  5. OnCellSelected(index, cellGo) — 选中管理（单选，切换 imgSelect 显示）
```

### BagItemCell.lua

```
职责：
  1. 绑定到单个格子 GameObject
  2. 响应点击：通知 BagPanelCtrl 选中
  3. 可选扩展：长按显示 Tooltip、拖拽交换、右键菜单
```

## 第四步：Tab 切换流程

```
用户点 TabItem
  → Toggle.onValueChanged
  → BagPanelCtrl.lua: OnTabChanged("item")
  → 从配置/服务器获取 items[] 数组
  → bagGridLayout:Refresh(#items)     -- C# 重算 Content 高度 + 回收
  → BagItemPool 逐个回调 OnCellBind   -- Lua 绑定图标、数量
  → 格子显示
```

切换 Tab 时 BagItemPool.RecycleAll() 回收所有格子，然后新数据走 Refresh 流程重新分配。

## 第五步：选中逻辑

```
用户点格子
  → BagItemCell.lua: OnClick()
  → BagPanelCtrl.lua: SelectCell(index)
      a. 取消上一选中：prevCell.imgSelect:SetActive(false)
      b. 设置当前选中：curCell.imgSelect:SetActive(true)
      c. 记录 curSelectIndex = index
```

## 实现顺序

```
第 1 步：修正 BagItemCell 结构（Button 在根节点，加 imgSelect）
第 2 步：C# BagItemPool.cs
第 3 步：C# BagGridLayout.cs
第 4 步：Content 挂 BagGridLayout，配置参数
第 5 步：Lua BagPanelCtrl.lua（Tab 切换 + 假数据验证）
第 6 步：Lua BagItemCell.lua（选中逻辑）
第 7 步：Game 视图验证滚动效果 + 截图
```

---

## 总结

| 层次 | 文件 | 职责 |
|------|------|------|
| C# | BagGridLayout.cs | 滚动监听、格子位置计算、Content 高度 |
| C# | BagItemPool.cs | 对象池：预实例化、分配、回收 |
| Lua | BagPanelCtrl.lua | Tab 切换、数据源管理、选中管理 |
| Lua | BagItemCell.lua | 单格交互（点击/长按/拖拽） |

GridLayoutGroup 不挂了，Content 只挂 RectTransform + BagGridLayout。
