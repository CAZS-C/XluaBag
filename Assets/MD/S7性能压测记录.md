# S7 性能压测记录（500 物品 / 虚拟滚动）

> 测试环境：Unity 2021.3.34f1c1，编辑器 Play Mode，Windows Standalone（PC）。
> 测试数据：临时把背包初始化为 **500 格**并塞入 **500 件装备**（装备 stackMax = 1，每件占一格）。
> 测试结束后已把存档还原为 **120 格 / 67 件物品**，不影响日常演示数据。
>
> **注意**：本文的 Frame Debugger 数字（27 events / 21 UGUI mesh）是「500 件物品顶部」的快照，
> 那一页的装备图标为空，**不能作为图标图集优化前的对比基线**。
> 图集优化需在默认存档的 Item Tab（22 个带图标格子）重新录基线。

## 一、结论

| 指标 | 实测结果 |
|------|----------|
| 物品数量 | 500 件（500 个槽位） |

| Frame Debugger 总事件数 | 27 |
| 其中 UGUI 合批 Mesh | 21 |

## 二、测试方法

1. 运行时执行 `pd:InitInventory(500)`，再用 `InventoryManager.AddItem` 放入 500 件装备，切到装备页。
2. 用 Lua 包装 `BagGridLayout.onCellBind` 统计重绑次数：
   - 静止观察两帧：`bindCount` 保持 28 不变；
   - 把滚动位置从顶部跳到中部：`bindCount` 28 → 56（只新增一次范围变化的重绑）。
3. 读取 `Content` 子物体数与激活数，并按格子位置反算显示索引：
   - 顶部：0 ~ 27
   - 中部：236 ~ 263
   - 底部：476 ~ 499
4. 打开 Frame Debugger，记录当前帧的渲染事件（27 个，其中 UGUI Mesh 21 个）。

## 四、发现的问题（后续可优化）

1. **批量添加会触发事件风暴**
   500 次 `AddItem` 每次都发 `OnSlotChanged` → Lua `Refresh` → `Sort` + `grid:Refresh` → 池子重建。
   由于 `Destroy` 延迟到帧末，同一帧内 `Content` 下会堆积 14056 个待销毁格子（实测）。
   真实业务应提供批量接口（批量添加完只刷新一次），或把刷新合并到帧末执行。

2. **图标未图集化，UGUI 合批被纹理打断**
   当前图标走 `Resources.Load` 单张加载，Frame Debugger 记录到 21 个 UGUI Mesh 批次。
   这是后续 DrawCall 优化的基线：可把图标合并进 SpriteAtlas，再复测批次数量。
