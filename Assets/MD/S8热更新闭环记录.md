# S8 热更新闭环记录

> 目标：把「Lua 能打进 AB」升级成「玩家能拿到新版本、校验、应用、失败回滚」。
> 环境：Unity 2021.3.34f1c1，PC（StandaloneWindows64），本地 HTTP 服务模拟 CDN。

---

## 一、链路

```text
LaunchScene（HotUpdateLauncher）
  → 读本地 state.json / StreamingAssets/PC/version.json
  → 请求 http://127.0.0.1:8000/PC/manifest.json
  → 比较 resVersion / minAppVersion
  → 按 md5 差量：只下载变化的 PC / lua / banner
  → 下载到 Res/{新版}.tmp（Range 续传 + 重试 + MD5 校验）
  → 校验通过 → 改名为 Res/{新版} → 写 state（current/pending）
  → 切换 ABMgr.BundleRoot → 加载 SampleScene
  → Main.lua 成功后 ConfirmCurrent()（pending = confirmed）
  → 下次启动若 pending != confirmed → 自动回滚到 previous
```

## 四、实测结果

### 1. 基础包 v1（无更新）

- LaunchScene 启动，`CheckAndUpdate` 请求失败（未开服务器）→ 走本地版本。
- Console：`[HotUpdate] 网络不可用，使用本地版本，正在进入游戏...`
- 进入 SampleScene，背包 67 件正常。

### 2. v1 → v2（只改 Lua/配置/公告）

发布 v2 后，本地缓存清空，`Assets/Lua` 临时改名（确保只走 AB）：

| 日志 / 检查项 | 结果 |
|---|---|
| 下载 | `PC` / `banner` / `lua` 三个包 |
| AB 命中 | 4 条 `[LuaMgr] 从 AB 加载 Lua`（配置、入口、面板、格子） |
| Lua 热更 | `LUA: [HOTFIX] Lua v2 loaded` |
| 配置热更 | `ItemDefinition.Get(1001).name = 铁剑·热更`（v1 为「铁剑」） |
| 非 Lua 资源 | `banner` TextAsset 内容为「XluaBag 热更公告 v2」 |
| 状态 | `current=2 previous=1 pending=2 confirmed=2` |
| 背包 | 67 件，装备 30 / 消耗品 22 / 宝石 15 |

`Res/2/` 实际文件：`PC`、`lua`、`banner`、`version.json`。

### 3. 回滚（模拟启动未确认）

手动把 `state.confirmed` 改为 1（模拟 v2 启动后未确认），关闭服务器后重启 LaunchScene：

| 日志 / 检查项 | 结果 |
|---|---|
| 回滚日志 | `[HotUpdate] 已回滚到资源版本 1` + `上次更新未完成，已回滚到上一版本` |
| 版本目录 | `Res/2` 被删除 |
| 启动版本 | 基础包 v1（AB） |
| 配置 | `ItemDefinition.Get(1001).name = 铁剑` |
| 状态 | `current=1 previous=1 pending=1 confirmed=1` |

### 4. 断点续传

`dev_server.py` 实测 `Range: bytes=0-9` → `206`，`Content-Range: bytes 0-9/20315`，返回 10 字节。
下载器在 `.part` 存在时带 Range 追加；服务器返回 200（忽略 Range）时会删除临时文件重新全量下载。

## 五、如何运行

1. 启动本地服务：

```powershell
cd HotUpdateServer
python dev_server.py --port 8000
```

2. Unity 打开 `Assets/Scenes/LaunchScene.unity`，Play。
3. 首次启动会从 StreamingAssets 基础包启动；如果服务器有更高版本，会先更新再进 SampleScene。
4. 发布新版本：改 Lua / `Banner.txt` → 菜单 `Tools/HotUpdate/2. 发布新版本`。
5. 清理本地缓存：菜单 `Tools/HotUpdate/3. 清理本地缓存`。

## 六、边界与后续

- **真机**：Android 的基础包拷贝逻辑已实现（`BaseBundleInstaller`），但本轮只验证了 PC；真机需要再跑一次 `UnityWebRequest` 读取 StreamingAssets 的路径。
- **安全**：manifest 没有签名，正式项目需要防篡改（签名/HTTPS）。
- **并发**：当前是顺序下载；并发 2-3 个包可作为后续优化。
- **灰度**：当前是全量清单；可按玩家/百分比返回不同 manifest 实现灰度。
- **包体**：当前只有 lua + banner；真实项目需要 AB 依赖分析、冗余资源合并、包体压缩策略。
- **强更**：`minAppVersion` / `forceUpdate` 已解析，PC 端未做完整交互测试。
